# Final review: paired gating, technical-null perturbation, and sample matching

These analyses add diagnostics without changing WiNN, its parameters, the simulation designs or Figure 2B–F. They use the production 0.1.6 source snapshot already committed under `scripts/targeted_validation/source_snapshot/winn/R/`, not the experimental permutation gate.

## Paired simulation gate comparison

`Rscript scripts/final_review_gating_matching/plot_paired_gate.R` reads the ten archived simulation seeds and computes each forced-policy RMSE minus selective/selective RMSE within each seed. Before pairing, the script requires exactly SIM01–SIM10 for each of the four unique policies and finite RMSE values; invalid or missing rows stop execution. Figure 2A shows all paired differences, zero, their mean and a two-sided 95% Student t interval (9 degrees of freedom). These are intervals over simulation realizations, not independent features. Results are under `generated/final_review_gating_matching/paired_gate_rmse*.csv`. The mean relative improvement for forced drift uses its unrounded mean RMSE as denominator (0.576%). Marginal policy summaries remain available in Supplement Figure S2.

## Technical-null perturbation

`Rscript scripts/final_review_gating_matching/null_correction_magnitude.R` replays every one of the existing 4,000 independent Gaussian null datasets: 100 features, 1,000 seeds at each of 20/50/100/200 injections, noise SD 0.15 on log1p, mean 3. Seeds are exactly `900000 + 10000*n + seed`. It applies the production conservative drift correction after MAD, with nominal BH threshold 0.05, adaptive Ljung–Box lag and fitdf 0. Batch and PQN are not applied. For every seed, the selected-feature count is read from the current correction diagnostics and asserted equal to the archived count. Changed-feature counts also exactly reproduce these current selection counts in all 4,000 datasets. RMS changes compare post-drift with post-MAD, isolating the incremental drift stage.

`summarize_null_magnitude.R` can also rerun the summary from saved replicates. It averages all-entry RMS changes over all datasets, including zero-change datasets. The affected-profile RMS is computed within each dataset over entries of changed features only; its reported mean averages only datasets with at least one changed feature. Thus it is not a pooled profile-weighted mean. False selections have small matrix-wide average effects in this design but can cause non-negligible changes in selected profiles. This analysis neither calibrates the gate nor establishes phenotype FDR or full-pipeline accuracy.

## Empirical selective versus forced drift

`Rscript scripts/final_review_gating_matching/empirical_gate_matching.R INPUT_DIRECTORY` uses `input_batchcorr_set1.rds` and `input_clinical_fiams.rds` from the prepared benchmark inputs, whose byte hashes are recorded in `input_and_source_hashes.csv`. These input files are private and are not included in the manuscript repository. The directory is also used as a local cache of fitted selective and forced matrices. Fixed preparation, selective batch adjustment and conservative PQN are retained; only the drift gate changes from selective to all. Corrected matrix dimensions, identifiers, finiteness and nonnegativity are checked. Aggregate matrix hashes are recorded. The selective/raw point estimates AND percentile intervals reproduce the archived main benchmark results to <1e-12.

Queries are study injections in BatchCorr and consecutive-injection pair means in the clinical dataset. The candidate pool contains every finite-similarity study profile in another batch, including separate acquisitions with the same biological identity. Repeated candidates are not collapsed or upweighted beyond one entry per acquisition/correction unit. Eligibility requires at least one same-identity candidate. Pearson correlation across all common log1p features ranks candidates; exact ties use stable original-column order. No exact top ties occur for raw, selective or forced outputs in either dataset. Top-1 success means the first candidate has the same identity.

BatchCorr has 693 eligible queries from 346 of 357 recorded identities, 635–667 candidates per query and 1–2 same-identity candidates. Clinical has 536 eligible queries from 267 recorded identities, 456–482 candidates and 1–3 same-identity candidates. These counts describe recorded analytical identities and do not assert patient-level independence. Uniform-random-candidate top-1 chance is the query average of the matching-candidate fraction: 0.1575% and 0.2176%, respectively.

The 2,000 paired biological-identity bootstrap draws use the archived seeds `2026072701+199` (BatchCorr) and `2026072701+1594` (clinical), retain all eligible-query counts per sampled identity, and use the same draws for every policy. Corrections, candidate pools and feature sets remain fixed; uncertainty does not include correction fitting. Selective-minus-forced matching point differences are +0.289 and +0.560 percentage points, but both intervals include zero. Thus the comparison supports modest point advantages, not established empirical superiority of the gate.

All published analysis outputs are aggregate and contain no clinical specimen identifiers. Session information and source/input hashes are included with results.
